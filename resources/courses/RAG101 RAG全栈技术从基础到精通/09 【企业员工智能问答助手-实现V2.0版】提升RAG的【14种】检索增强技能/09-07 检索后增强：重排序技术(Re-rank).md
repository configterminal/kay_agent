# 09-07 检索后增强：重排序技术(Re-rank)

[0:00] 在前面的小节中,我们讲解了很多关于提升检索性能的方法。
[0:05] 这些方法的结果就是生成了很多基于相似度计算得到的与问题相似的一些文档。
[0:15] 这个时候,我们通常需要对这些检索得到的文档进行再次的筛选,
[0:22] 而不是将这些文档都作为上下文信息送到大语言模型。
[0:28] 我们称这个筛选的过程为重排序,re-rank。
[0:35] 之所以要进行re-rank或者说重排序,
[0:41] 一方面是检索到的文档是基于相似度查询得到的一些相似的文档。
[0:49] 而有时候会因为Inbany模型内在的一些原因,
[0:53] 会出现Inbany相似度上很高的一些文档,
[0:58] 但是和问题却是不那么相关,
[1:03] 也就会出现很相似但是不那么相关的一些文档。
[1:08] 我们是希望重排序把这些文档给筛选掉。
[1:13] 另外一个原因是说,检索到的上下文信息如果太多,
[1:19] 检索到的文档如果太多的话,
[1:23] 直接送到大语言模型,

[1:37] 同时也有可能引入一些不相关的上下文信息。
[1:42] 所以说需要对这些检索到的众多的文档再次的进行精简。
[1:47] 精简的过程就是文档的重排序。
[1:51] 重排序的目的就是使那些与孕妇输入问题更相关,
[1:57] 更准确的文档分块,
[1:59] 它的排名会在所有的文档里面排名更靠前,
[2:03] 这样更容易让我们筛选出来,
[2:06] 作为上下文信息,加入到大语言模型。
