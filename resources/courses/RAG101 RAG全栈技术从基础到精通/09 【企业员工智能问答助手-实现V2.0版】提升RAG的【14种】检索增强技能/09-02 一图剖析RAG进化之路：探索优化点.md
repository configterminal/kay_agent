# 09-02 一图剖析RAG进化之路：探索优化点

[0:00] 相关的上下文信息合并起来一起送到大语言模型里面去,来进行生产答案。
[0:09] 这里需要注意的是,用户的问题是不可控的。
[0:13] 有不同的写法,有不同的描述,是多种多样的。
[0:17] 而基于相似度匹配的上下文信息,不一定能得到高质量的上下文。
[0:26] 这些不好的或者说有噪声的上下文信息,就会影响答案的质量。
[0:34] 还有很多检索过程中存在的一些问题,后面会实际讲到。
[0:39] 针对这些问题,有没有什么改进的方法呢?
[0:43] 人们在普通的这种RAG的基础上,增加了一些额外的一些操作,来提升检索的性能。
[0:55] 总的来说,有两种不同的解决方案。
[0:58] 如果是以检索模块为界限,可以分为检索前的增强,和检索后的增强。
[1:06] 检索前的增强,主要是从问题角度出发。
[1:10] 比如说对问题进行改写,对问题进行扩充,来增加一些额外的信息。
[1:17] 这样就可以增加与知识库中文档相关性的一些匹配程度。
[1:23] 而检索后的增强,主要是对检索后的上下文信息进行处理。
[1:30] 比如说融合多种不同的检索策略。
[1:33] 还有一个更普遍的方法,就是对上下文的信息进行相关性的存牌。
[1:41] 然后选择与问题最相关的那些上下文信息,输入到大远模型。
[1:46] 这些方法,我们后面都会详细的进行讲解。
[1:50] 还有一种方法是从系统性或者从模块化的角度来设计RAG的流程。
[1:58] 也就是说,它从总体或者说整体的角度来优化整个RAG的流程。
[2:09] 比如说它在RAG流程中加入了一些验证判别的模块。
[2:15] 比较聪明的方法就是Self-RAG。
[2:20] 另外一个就是,它不是通过单次的这种RAG流程,
[2:27] 而是通过多次迭代的这种方式来做检索增强,以此来提升RAG的一个效果。
[2:35] 从这些流程框架中我们可以看到,对于普通的RAG还是有很多不同的方法来提升RAG的一个性能。
[2:45] 在后面的小节中,我们会针对这些方法进行逐一的讲解。
[2:50] 并且实现,让大家在实际的RAG开发过程中有更多的工具或者说优化的方法去提升你的RAG的一个效果。
