# 06-02 复杂：企业数据复杂多样

[0:00] 我们要进行文档处理,就必须对这些文档或者数据有一定的认识,所谓知己知彼。
[0:07] 所以说我们在这一小节就来了解一下企业数据的复杂多样性。
[0:12] 不同企业因为经营性质的不同,就会产生各种各样的一个数据。
[0:17] 有些数据还是企业内部独有的一个数据。
[0:21] 所以有时候在处理数据时,就需要自己来写脚本来做数据的解析。
[0:27] 说到企业数据的复杂性,总的来说可以分为格式的复杂性和内容的复杂性。
[0:33] 我们先来讲解一下什么是格式的复杂性。
[0:36] 我们先来看一下格式的复杂性。
[0:39] 我们把企业的数据分为两大类,一类是结构化的数据,一类是非结构化或者半结构化的一个数据。
[0:47] 对于非结构化或者半结构化数据,
[0:51] 像PDF、Word、PPT、Excel这些都是办公和绿常生活中最常见的文档格式。
[0:59] 通常企业中的产品文档、报表数据都是以这样的文件格式存在的。
[1:04] 而像TXT这种是纯文本的数据,当然不一定是以TXT为后缀,
[1:11] 比如企业应用中的一些绿字的数据也可以认为是一个纯文本的数据。
[1:18] 另外还有像HTML、JSON、XML这样的标记语言数据,
[1:24] 像HTML网页数据就包括企业内部的一些Wiki的文档。
[1:30] 而JSON跟XML一般是企业内部数据传递的一个格式,
[1:34] 特别是接口啊,还有一些配置文件之间。
[1:38] 另外一个是MACDOT,MACDOT现在也是很多人在使用的一种轻量级的标记语言。
[1:44] MACDOT常用于编写像REDME这种文件,还有一些技术的文档,
[1:50] 还有我经常用来做一些学习的笔记等等。
[1:53] 另外还有图片和视频,现在也是非常常见的一个文件格式。
[1:59] 所有的这些都是非结构化跟半结构化的一个数据,
[2:04] 当然这里只罗列了一些比较常见的数据格式。
[2:08] 相对于非结构化或半结构化的数据,
[2:11] 结构化的数据典型的代表就是我们常见的关系型数据库,
[2:16] 比如说MyCircle,Oracle这种典型的传统的关系型数据库。
[2:22] 结构化数据的一个特点就是它数据是由特定的字段组成的,
[2:26] 它的结构是固定的,也就是这些字段在数据创建的时候就固定下来了。
[2:32] 字段有明确的含义,可以很方便的解析和读取。
[2:35] 除了刚才说过的MyCircle和Oracle这样的关系型数据库,
[2:40] 还有一些是像文档型的数据库,像MangoDB,还有像文档检索的数据库。
[2:47] ElectricSearch就是我们常说的ES,以及列式的数据库,
[2:52] 现在也是在做数据分析Orap里面比较常见的数据库,
[2:57] ClickHouse它是以列式来存储的,以及图数据库,
[3:01] 像NEO4J,还有就是像典型的分布式的NodeCircle的数据库,
[3:07] 这些结构化的数据一般是存储企业内部比较重要的业务的数据,
[3:13] 只要根据指定的数据库类型的查询语言就可以进行查询。
[3:17] 这种查询语言一般是像社口语言,或者类似的这种类社口的查询语言。
[3:23] 所以说对于结构化数据来说,它的解析是比较固定的,相对来说是比较容易的。
[3:29] 而非结构和半结构化数据,因为它内容是多样的,不确定的,
[3:34] 所以说解析起来就存在一定的难度。
[3:36] 企业数据的复杂性,还有另外一个方面是它内容的复杂性,
[3:42] 特别是对于非结构化的数据处理来说,它处理是比较棘手的。
[3:47] 有很多时候都是需要进行特殊处理,
[3:51] 比如一个PTL文档,它里面就有可能包括文章的标题,
[3:56] 文档的标题,以及文档的段落,
[4:00] 还要包括表格数据,还要包括图片的数据。
[4:06] 另外也是有包括很多公式,
[4:09] 另外一个是不同的文档,它有不同的版式,
[4:12] 布局也是不一样的,比如有双列的布局,
[4:15] 版式上面有,比如说有文本,有标题,有列表,有表格,有图片,等等。
[4:22] 它的排版是多种多样的,而且是零否多变的。
[4:25] 正是企业数据的复杂多样,增加了构建知识库的一个难度。
[4:30] 在必要的情况下,要做很多特殊处理,
[4:33] 来保证处理数据的一个质量。
