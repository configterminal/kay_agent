# 07-04 项目架构设计

[0:00] 然后是系统的总理设计,我这里用DrawIO画了一个模块图。
[0:05] 从这个图可以看出,整个的RAG的系统分为两个大的部分。
[0:12] 第一个部分是内部的知识库的一个构建的过程。
[0:17] 另外一个是外部的问题检索的PubLine的一个模块。
[0:23] 其中,知识库的构建过程包括对项目文档的读取解析,
[0:30] 进行文本分块,并对分块后的文本用Inviting模型进行限量化的处理,
[0:37] 然后传入构建好的限量数据库中。
[0:40] 第二部分是外部运负的一个检索过程。
[0:44] 当员工在运负界面上输入一个问题时,
[0:48] 首先会触发一个限量检索的一个过程。
[0:51] 这个过程会将问题发到构建好的知识库中进行相似性的一个检索,
[0:58] 然后得到一些相关的一些文档信息。
[1:02] 这些相关的文档作为上下文信息和员工的问题一起合并到一个提示池里面去,
[1:10] 输入到大远模型中去生成答案。
[1:14] 同时,这些相关的上下文信息也作为参考信息和答案一起展示在前端界面中,
[1:22] 让员工清晰的了解这些生成的答案是有依据的,
[1:27] 增加这些结果的可解释性。
[1:30] 从这张图我们就可以清晰了解到系统要实现的功能模块,
[1:35] 一个良好的应用设计可以促进快速的迭代开发。
