# 07-06 总结和展望：转变思想，AI应用开发和传统软件开发的区别

[0:00] 最后我们来总结一下,在这一章中我们构建了一个针对企业员工的制度问答助手
[0:07] 我们按照软件开发的过程,做了项目的需求分析,包括痛点分析、功能需求和依赖数据的一些分析
[0:16] 以及在此基础上做了系统初步的技术选行
[0:21] 编辑项目做了总体的设计,最后是根据这个设计,在实战中实现了这个RAG的系统
[0:30] 最后我们来回答一个问题,为什么我们称这个系统为BaseLine的一个版本呢?
[0:36] 究竟原因是我们没有经过一个完备性的测试,这个系统是否符合上限要求,它是存疑的
[0:44] 我们后面需要在这个BaseLine的基础上,快速地进行迭代测试,以获取更优的一个版本
[0:53] 为什么需要这样呢?这里就需要涉及到传统的软件开发和AI应用开发的一个区别
[1:01] 我们先来看一下软件开发的一个生命周期
[1:05] 正如前面的项目分析一样,我们都是从需求分析开始的
[1:10] 在需求分析确定了功能点以后,会对系统进行功能性的设计
[1:15] 然后针对设计,包括概要设计和详细设计进行代码的开发
[1:20] 开发完成之后,进行功能测试,测试通过之后进行升级部署
[1:27] 后面就进入运轨的阶段,这个就是整个软件开发的一个生命周期
[1:34] 我们在上面开发企业员工的制度问档助手的时候,也是根据这个软件开发的流程进行开发的
[1:42] 虽然传统的软件开发和AI应用开发的整个开发周期总流程是一样的
[1:49] 但是具体的实施细节是不一样的,主要是体现在应对不确定性的问题上面
[1:56] 首先是传统的软件开发,针对功能需求,按照设计方案开发要达到的功能结果输出是确定的
[2:05] 也就是说进入开发之前就知道开发的一个结果,整个过程是一个明晰的
[2:12] 只要按照设计开发就可以一步到位
[2:15] 而AI应用开发,由于它的每个过程都存在一定程度的不确定性
[2:21] 即使最初的设计方案定下来以后,还是会因为孕妇输入的多样性
[2:27] 还有诸如大语言模型生成结果,它具有一定的绥靖性
[2:33] 所有这些都造成的结果有着不确定的成分
[2:37] 所以和传统的软件开发不同的是
[2:40] AI应用开发在开发一开始时,是无法准确地知道开发的结果是否符合预期的
[2:47] 这个也是AI应用开发中引入智能所带来的问题
[2:52] 当然如果说这个智能足够的强大,或许就不存在这个问题了
[2:56] 从另外一个角度来说,传统的软件开发是基于规则的,它是确定性的
[3:02] 而AI应用开发它是基于智能的,它是可能存在不确定性的因素的
[3:08] 正是因为AI应用开发存在这种不确定性
[3:12] 我们就要先构建一个可测试的Baseline的基线版本
[3:17] 然后在这个基线版本上快速的迭代来提升性能
[3:21] 最终得到一个可交互的版本
[3:25] 所以在AI应用开发中,需要建立一个Baseline的思维
[3:30] 也就是我们应该快速的构建一个可测试的基线版本
[3:35] 然后通过构建一个符合业务场景的测试数据
[3:39] 对这个基线版本进行测试评估
[3:43] 然后根据测试评估的效果,来迭代改进系统的性能
[3:48] 这个测试迭代的过程可能是多次的
[3:51] 即使在满足测试要求上线部署以后
[3:55] 也是需要不断的去收集线上的数据,进行更多的迭代更新
[4:00] 因为可能你最初构建的测试数据
[4:03] 并不能覆盖实际中的所有的应用场景
[4:07] 所以说也要注重发布后运为数据的收集
[4:11] 然后不断的利用这个收集的数据进行迭代提升系统的性能
[4:16] 这个思维在机器学习和声后学习的模型训练过程中也是适用的
[4:22] 所以说我们在AI应用开发中,我们要有这个思维上的一个转变
