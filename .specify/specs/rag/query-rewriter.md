# query_rewriter.py — 查询重写

```
┌─────────────────────────────────────────────────────────────────┐
│                      query_rewriter.py                           │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  rewrite_query(raw_query, chat_history) → list[str]              │
│       │                                                         │
│       ├── ① classify_query(query) → QueryType                    │
│       │     判断问题类型（1 次轻量 LLM 调用）                      │
│       │     ├── AMBIGUOUS  → 有指代词或依赖上下文               │
│       │     ├── FUZZY      → 太短太泛，缺少术语                  │
│       │     ├── VERBOSE    → 有术语但表达啰嗦                    │
│       │     └── DIRECT     → 已经很清晰，不需重写                │
│       │                                                         │
│       ├── ② 按类型执行（只跑选中的）                              │
│       │     ┌──────────────────────────────────────────────┐    │
│       │     │ AMBIGUOUS  → history_rewrite(query, history)  │    │
│       │     │              指代消解 + 补全上下文              │    │
│       │     │                                              │    │
│       │     │ FUZZY      → hyde(query)                     │    │
│       │     │              生成假答案 → 用假答案去搜         │    │
│       │     │                                              │    │
│       │     │ VERBOSE    → multiquery(query, count=3)      │    │
│       │     │              3 个不同角度重写                  │    │
│       │     │                                              │    │
│       │     │ DIRECT     → 透传 [query]                    │    │
│       │     └──────────────────────────────────────────────┘    │
│       │                                                         │
│       └── 返回：1~3 条优化查询                                   │
│                                                                 │
│  Fallback：LLM 失败 → 返回 [raw_query]                           │
└─────────────────────────────────────────────────────────────────┘
```

## 三个子函数

### history_rewrite(query, history) → str

指代消解 + 上下文补全。替换"那个""这个""它"为历史中的具体内容，保留课程编号。

```
你是查询重写助手。结合对话历史，把学员的模糊问题改写成适合知识库检索的精确查询。

规则：
1. 把指代词（那个、这个、它、他说的、前面讲的）替换成历史中的具体内容
2. 补全口语化表达，但不要添加学员没问的内容
3. 保留课程编号（如 "2-3"、"第2章"），不要改掉
4. 只输出改写后的问题，不要任何解释

对话历史：
{history}

学员当前问题：{query}

改写后：
```

### hyde(query) → str

假答案生成。LLM 假装老师回答，生成的文本跟课程文档风格更接近，搜索匹配度更高。

```
假设你是这门课程的老师。请用一段话回答学生的问题。
不需要回答得完全准确，但要用课程讲义的风格和术语来表达。

问题：{query}

假答案：
```

### multiquery(query, count=3) → list[str]

多角度重写。用不同措辞表达同一个问题，提高召回。

```
你是一个搜索查询专家。把下面这个问题改写成 3 个不同角度的搜索查询，
帮助从课程知识库中找到最全面的答案。

要求：
- 3 个查询用不同的措辞和角度
- 如果问题有技术术语，至少一个查询用通俗表达
- 如果问题太简短，至少一个查询补全相关上下文
- 输出严格 JSON 数组格式：["查询1", "查询2", "查询3"]

问题：{query}
```

## 分类 Prompt

```
判断以下学员问题的类型，只输出一个词：

- ambiguous：包含指代词（那个、这个、它、前面讲的）或依赖对话上下文才能理解
- fuzzy：太简短或太口语化，缺少具体术语
- verbose：有明确术语但表达啰嗦，需要多角度重写
- direct：已经很清晰，可以直接用于搜索

问题：{query}
```

## 对比旧版

|                   | 旧版         | 新版                 |
| ----------------- | ------------ | -------------------- |
| 每次调用 LLM 次数 | 3 次         | 1~2 次               |
| DIRECT 场景       | 也跑三种重写 | 直接透传，零额外调用 |
| 输出查询数        | 最多 5 条    | 1~3 条               |
| 召回效果          | 可能引入噪音 | 只跑最合适的         |
