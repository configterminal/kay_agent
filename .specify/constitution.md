# 项目宪法 (Constitution)

> AI 助教系统 — 核心原则与不可违反的规则

## 技术原则

1. **文档驱动开发** — 加新模块、改架构、跨 2+ 文件，必须先出方案文档到 `.specify/specs/`，你审核通过后才编码
2. **接口先行** — 前后端联动必须先定 API Spec（OpenAPI 或文档），双方按契约并行开发
3. **渐进式** — 先跑通核心链路，再逐层加防御（缓存、限流、重试）
4. **可插拔设计** — 推理/语音/记忆等基础设施通过 Provider 模式抽象，默认 local，生产可切 http

## 代码规范

- 每个模块、类、公开方法必须有简短的中文注释说明用途
- 复杂逻辑加行内注释解释"为什么这样做"
- 函数保持单一职责，不超过 50 行为佳
- 命名：模块用 snake_case，类用 PascalCase，函数和变量用 snake_case

## 禁止事项

- ❌ 硬编码任何课程数据
- ❌ 跨模块直接 import 内部实现
- ❌ 无注释的复杂逻辑
- ❌ 未经你同意擅自降级技术方案（如 RedisSaver → MemorySaver）
- ❌ 遇到兼容性问题时绕过而非解决
- ❌ **禁止修改、覆盖、截断、删除 `.env` 文件** — 该文件包含你私密配置，损坏不可恢复
- ❌ **禁止以任何方式操作 `.env` 文件**（包括但不限于写入、追加、重命名、chmod、复制到其他路径）
- ❌ **禁止读取 `.env` 内容作为测试数据或注入到 prompt 中**
- ⚠️ **每次需要涉及 `.env` 文件时，必须单独向你确认** — 即使你在之前的对话中同意了其他操作，也不代表同意操作 `.env`。涉及 `.env` 的操作需要显式的、针对该操作的明确同意

## Prompt 管理规范

- Agent System Prompt 统一由 `src/agents/prompts/` 模块运行时组装
- 组装公式：shared_base(L2-L5) + coach(L6) + emotion(L7) + role(L1)
- 共享规则（安全、工具协议）只改 shared.py 一处
- 各 Agent 专属职责只改对应文件
